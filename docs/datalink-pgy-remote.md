# 跨省数据链验证（蒲公英 · 一页纸）

> 场景：两台机器相隔约四分之一个中国，走**蒲公英**异地组网。
> 目标：在不开游戏的前提下，先证明「包能双向过去、报文没被改、3 秒超时下不掉线」。
> 预计耗时：组网 5 分钟 + 链路 10 分钟 + 接游戏 10 分钟。

---

## 0. 先明确三件事（免得白折腾）

1. **蒲公英给的是虚拟局域网（三层）**，不是网页代理。UDP 直接走虚拟网卡，
   不需要端口映射、不需要动路由器。
2. **延迟不影响正确性**。数据链 4 Hz、每包约 45 字节，共享的高度是慢变量
   （Vy 通常 0–5 m/s，100 ms 只差半米）。跨省 30–150 ms 完全够用。
3. **要验证的只有三条**：双向可达、报文完整、3 秒内至少收到一包。
   这三条过了，游戏里就一定能用；反过来，游戏里出问题也一定先回这三条上找。

---

## 1. 两端组网

两台机器各做一遍：

| 步骤 | 操作 | 判据 |
|---|---|---|
| 1 | 装蒲公英客户端，登录**同一个账号**（或让对方接受邀请加入同一网络） | 网络列表里能看到**两台**设备，状态都是「在线」 |
| 2 | 记下本机虚拟 IP：**看网卡名，不要看网段** | 网卡名含 `Oray` / `蒲公英` / `VpnEnt`，那一行的 IPv4 就是 |
| 3 | 确认虚拟网卡是「已连接」 | 该网卡有地址（不要求有网关） |

查本机地址用这条，一眼能看出哪块网卡是蒲公英：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Select-Object IPAddress, InterfaceAlias
```

> ★ 本机实测：`OrayBoxVpnEnt` 拿到的是 **`172.16.1.229`**。
> 蒲公英按组网模式可能给 `16.x`、`17.x`，也可能给 `172.16.x` ——
> 和 VMware / 家用路由器的私有段长得很像，**只能靠网卡名认**。
> `datalink-test.ps1` 会自动把带 Oray 的网卡标出来。

然后在一台上 ping 另一台（换成对方的虚拟 IP）：

```powershell
ping 172.16.1.69
```

| 结果 | 判断 |
|---|---|
| 4 发 4 收，RTT 20–60 ms | P2P 打洞成功，最好情况 |
| 4 发 4 收，RTT 80–200 ms | 走贝锐中继，**仍然可用**，不用管 |
| 偶尔超时但能通 | 可用，但要在第 4 步重点看丢包 |
| 全超时 | 别往下走，先查蒲公英（见第 6 节） |

> ★ 蒲公英免费版限 3 个设备、有带宽限制。本协议 4 Hz × 45 B ≈ **1.4 kbps**，
> 限速对它没有影响。

## 2. 防火墙一次到位（两端都要，管理员 PowerShell）

```powershell
New-NetFirewallRule -DisplayName "WtHud DataLink" -Direction Inbound -Protocol UDP -LocalPort 48017 -Action Allow -Profile Any
```

`-Profile Any` 是必须的：**蒲公英虚拟网卡通常被 Windows 判成「公用网络」**，
只放行「专用」的规则对它无效，而且不会有任何提示。

同时检查国产安全软件（360 / 腾讯管家 / 火绒）的「网络防护」——
它们拦 UDP 入站比 Windows 防火墙更常见，且默认静默拦截。

## 3. 第一枪：链路通不通（不用游戏、不用 HUD 界面）

### 3.A 推荐先做：一条命令，一轮测双向（共 13 KB，不用传 exe）

**最省事：双击 `start-test.bat`，按提示输入对方的虚拟 IP，回车。**
不用敲命令、不用 cd、不用管执行策略。

> 如果双击后一闪而过或者被拦：右键 `start-test.bat` → 属性 → 勾「解除锁定」。
> 还不行就用下面的命令行方式。

命令行方式，**先 cd 到脚本所在的文件夹**，否则会报「.ps1 不存在」：

```powershell
cd "$env:USERPROFILE\Desktop\WtHud-数据链联调"
```

然后（`172.16.1.69` 换成对方的虚拟 IP，**不要带尖括号**）：

```powershell
.\datalink-test.ps1 -Peer 172.16.1.69
```

它会先列出本机所有 IPv4 并标出蒲公英那块网卡，再开两个窗口：一个收、一个发。
两端都跑这一条，**A→B 和 B→A 就在同一轮里验完了**。

加 `-Seconds 300` 就是五分钟稳定性；加 `-DryRun` 只打印命令不开窗口。

<details>
<summary>不想用一键脚本？手动开两个窗口（等价）</summary>

```powershell
# 窗口 1：收（占住 48017）
.\fakedatalink-recv.ps1 -Seconds 120

# 窗口 2：发给对方
.\fakedatalink.ps1 -Target 172.16.1.69:48017 -Seconds 120
```

发送端不占 48017，所以收和发能在同一台机器上同时跑。
如果提示「无法加载文件，因为在此系统上禁止运行脚本」，改成：

```powershell
powershell -ExecutionPolicy Bypass -File .\fakedatalink-recv.ps1 -Seconds 120
powershell -ExecutionPolicy Bypass -File .\fakedatalink.ps1 -Target 172.16.1.69:48017 -Seconds 120
```

</details>

★ PowerShell 里 `<` 是重定向符号。看到 `“<”运算符是为将来使用而保留的`，
就是把占位符的尖括号一起抄进去了 —— 地址只能写数字和点。

两边窗口各出现这种行就通了：

```
  14:02:11.337  from 172.16.1.69:52311        id=777777  alt= 3012m  vy=  10.0  hdg= 184  turn=   0.0  bank=     -  pos=0.52000,0.50000
```

判据（**两边各自**都要满足）：

| `rx`（120 s，期望 480） | 结论 |
|---|---|
| ≥ 408（85%） | **通过** |
| 1–407 | 通了但丢包严重，先别接游戏，按第 4 步定位 |
| 0 | 不通，跳到第 6 节 |
| `bad > 0` | 包到了但解析失败 —— 报文被中间设备改写了，把原始行贴出来 |

### 3.B 更接近真实：用 HUD 自己的解析器（需要 exe）

脚本的解析规则是照着 `DataLink.TryParsePayload` 抄的，但毕竟是两份代码。
想用真家伙验一遍时，把收的那一端换成 `dlprobe`：

```powershell
.\WtHud.exe dlprobe 120
```

窗口停在 `listening on udp 48017 for 120s`。**别关，也别同时开 HUD**（抢同一个端口）。

另一端照旧用 `fakedatalink.ps1` 发。判据与 3.A 相同。
★ 这一路是**单向**的，换方向要交换角色再跑一遍。

> ★ UDP 没有「连接」概念，**不能用 telnet / `Test-NetConnection -Port` 测**（那是 TCP）。
> 唯一可靠的判据就是 `rx` 计数在涨。

## 4. 第二枪：五分钟稳定性

### 4.1 反向别省

用 3.A（两边同时收发）时，双向已经在同一轮里验过了，可以跳过这一条。
只走了 3.B（`dlprobe` 单向）的，**必须交换角色再跑一遍**。

★ NAT 打洞有可能**只通一个方向**：A 发的包能到 B，B 发的包到不了 A。
这时候单向 `rx` 正常、双向就废 —— 编队里表现是「我看见他、他看不见我」，
最难查。所以两个方向都要各自 ≥ 85%。

### 4.2 五分钟

两边同时跑（就是 3.A 那条命令，把时长改成 300）：

```powershell
.\datalink-test.ps1 -Peer 172.16.1.69 -Seconds 300
```

| 指标 | 期望 | 门槛 |
|---|---|---|
| `rx`（300 s，期望 1200） | 1200 | ≥ 1140（95%） |
| 连续丢包 | 0 | **≤ 11 包**（3 s 超时 = 12 包，超了 HUD 会闪 `no partner`） |
| `nodes` | 1 | 恒为 1；忽 0 忽 1 说明丢包已经踩线 |

连续丢包怎么数：收端每行都有毫秒时间戳，相邻两行的间隔
`> 750 ms`（3 个周期）就记一次异常，`> 3000 ms` 就是一次掉线。

## 5. 第三枪：接进 HUD（真验收）

两端都开 HUD，**F1 → 编队**，在数据链那几行填：

| 行 | 填什么 |
|---|---|
| 使用数据互联 | 开 |
| 对端地址 | `172.16.1.69:48017`（多个用逗号分隔；留空 = 广播，跨省一定不通） |
| 发送目标 | 自动变成 `1 target(s)`；显示 `1 ok / 1 bad` 说明地址格式写错了 |

改完**立即生效**，不用重启。然后按这张表逐项打勾：

| # | 看哪里 | 应该看到 | 说明 |
|---|---|---|---|
| 1 | 面板「数据链状态」 | `no partner` → `linked #ID (by role)` | 括号里是识别依据：by id 手填、by role 对方自称长机、solo 只有一个节点、ambiguous! 有歧义 |
| 1b | 面板「在线节点」 | `#777777L 3143m 0.2s` | L=自报长机 W=自报僚机 ?=旧版；包龄一直涨说明在丢包 |
| 1c | 面板「僚机站位」 | `W1 ok · W2 掉队 480m` | 僚机自己判、自己报；长机 HUD 上同步显示最严重那一架 |
| 2 | 面板「节点 ID」 | 两端不同 | 相同说明撞 ID，改一端配置里的 `dataLinkId` |
| 3 | 僚机屏幕 | 出现 `长机 R54°` | 需要**长机按转向辅助键**（默认 Ctrl+Shift+T）并压坡度，这是目标坡度广播真的到了的证据 |
| 4 | 僚机槽位表高度 | 出现数字，且 = 长机高度 − 本机高度 | 拿两边仪表交叉核对，差 5 m 内算对 |
| 5 | 长机屏幕 | 僚机转向提示不抖 | 4 Hz 下正常是每 250 ms 一跳，抖成随机数说明丢包 |

五项全过 = 链路验收通过。

## 6. 不通怎么排（按顺序，别跳）

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| ping 就不通 | 两端不在同一蒲公英网络 / 未同时在线 | 网络成员列表里确认两台都在线 |
| ping 通，`rx=0` | Windows 防火墙按「公用网络」拦了 | 重跑第 2 节那条命令，`-Profile Any` |
| ping 通，`rx=0`，防火墙已放行 | 360/管家/火绒拦 UDP | 退出或把 `WtHud.exe` 加白 |
| 一个方向通、反向不通 | 对称 NAT，打洞只成功一半 | 蒲公英后台切换「转发模式」/ 换中继，或改 ZeroTier |
| `rx` 在涨、`bad` 也在涨 | 报文被改写或截断 | 贴出 B 窗口原始行 + A 的完整输出 |
| `rx` 在涨、`nodes=0` | 发送端 ID 和接收端撞了 | 换个 `-Id`，或改配置里的 `dataLinkId` |
| `cannot bind udp 48017` | 端口被占（常见：HUD 还开着） | `Get-Process WtHud`，关掉再跑 |

★ 如果蒲公英客户端让跑游戏的那台机器蓝屏（`0x133 DPC_WATCHDOG_VIOLATION`，
VGC 驱动已知问题），别硬扛：换 **ZeroTier**（用户态虚拟网卡，不打内核补丁），
验证步骤完全一样，只把虚拟 IP 换掉。

## 8. 为什么这套判据够用

- **4 Hz + 3 s 超时**：要连续丢 12 个包才会掉线，链路容错是 12 倍周期。
  跨省链路哪怕 20% 丢包，也不会出现「连接/断开」反复跳。
- **报文 45 字节**：远小于任何链路的 MTU，不会被分片，不存在「大包过不去」。
- **高度是慢变量**：这是整个协议敢用 4 Hz 的原因。延迟 200 ms 时高度只差 1 m，
  而编队判定门槛是 30 m —— 差了 30 倍，测不出来。
- **快变量只有一个**：长机的目标坡度。它 250 ms 更新一次，加上 60 ms 延迟，
  最坏滞后 310 ms。转向辅助本来就是稳态量（看的是「该压多少度」不是「这一帧」），
  所以这个滞后可以接受，不需要加时间戳或升协议版本。
