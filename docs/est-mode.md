# WtHud 的「AHRS EST」是怎么算出来的

> 面向用户/提问者的说明文档。回答「为什么我的 HUD 显示 AHRS EST？它到底怎么工作？」
> 代码位置：`Telemetry/AttitudeFusion.cs`、`Telemetry/TelemetrySnapshot.cs`（`FlightPathAngleDeg`）、
> `Telemetry/TelemetryParser.cs`、`Hud/HudGeometry.cs`（`AddSourceLabel` / `AddPitchLadder`）。

## 0. 一句话

**GAME = 直接读游戏给的地平仪数据；EST = 游戏没给地平仪时，HUD 用其他飞行数据把姿态"算"出来。**
这是**自动选择**的，没有「EST 开关」：同一个 `/indicators` 接口，有的机型带 `aviahorizon_pitch/roll`，
有的（主要是顶级喷气）不带，HUD 按实际拿到的数据决定走哪条路。

## 1. 什么时候是 EST

War Thunder 的 8111 `/indicators` 里：

- 有 `aviahorizon_pitch` / `aviahorizon_roll`（或退而求其次的 `bank`）→ **AHRS GAME**
- 没有 → **AHRS EST**

螺旋桨/早期喷气大多有原生地平仪；顶级喷气（F-16、F/A-18、苏系等大量机型）没有，所以只能估算。
`airframes.json` 里每个机型会自动记录 `attitude: "game" | "est"`，可以自己查。

## 2. EST 用到的原始数据

全部来自 8111 的 `/state`，加上 `/indicators` 里的罗盘：

| 数据 | 字段 | 用途 |
|---|---|---|
| 升降速度 | `Vy, m/s` | 算航迹倾角 γ |
| 真空速 | `TAS, km/h` | 算航迹倾角 / 转弯坡度 |
| 迎角 | `AoA, deg` | 机身纵轴相对航迹的夹角 |
| 滚转角速度 | `Wx, deg/s` | 无罗盘机型时积分坡度 |
| 法向过载 | `Ny` | 置信度（大 G 机动时降权） |
| 航向 | `/indicators` 的 `compass` | 算转弯角速度 |
| 任务时间 | `ElapsedSeconds` | 时间窗口/滤波 |

## 3. 俯仰角：航迹角 + 迎角

```
γ  = asin( Vy / TAS )                // 航迹倾角（爬升/下滑角）
俯仰 = γ + AoA                       // 机身纵轴俯仰角
```

- `Vy` 是垂直速度，`TAS` 是真空速；两者相除得到航迹相对水平面的倾角。
- 再叠加上**迎角**，就是机头（机身纵轴）相对水平面的角度。
- 结果做 0.45 系数的低通，避免 25 Hz 数据抖动直接传到梯子上。

**它为什么能对**：平飞时 γ≈0、俯仰≈AoA；爬升时 γ 为正，俯仰更大；俯冲时 γ 为负。
**误差来源**：垂直气流/热气流（Vy 里混入空气团运动）、侧滑、AoA 传感器噪声、低空/低速时 TAS 小导致 γ 放大。
所以大机动、乱流里 EST 的俯仰会比座舱仪表"慢半拍"或略有偏差，这是估算方式的固有代价。

## 4. 坡度角：协调转弯公式

```
ω    = 航向角变化率（约 1.6 s 窗口的线性趋势，deg/s）
坡度 = atan( TAS·ω / g )             // 协调转弯：bank = atan(V·ω/g)
```

几个实现细节（都是踩坑后定下来的）：

1. **航向趋势用约 1.6 秒窗口，不逐帧微分**：8111 的航向是量化过的，逐帧差分噪声巨大（实测平均误差 14.6°）。
2. **算出的坡度限幅 ±80°**，`|坡度| < 6°` 时当作 0，避免平飞时梯子来回抖。
3. **显示值以 140°/s 的限制趋近目标**：转弯能跟上，平飞又能回到 0。
4. **为什么不用 `acos(1/Ny)` 算坡度**：那个公式只对"稳定水平转弯"成立。筋斗/急拉时 Ny 能到 7–10，
   公式会算出 80°+ 坡度，而机翼明明是平的——实测表现为俯仰梯疯狂旋转。所以弃用。
5. **没有罗盘的机型**（例如 Rafale C）：航向变化率恒为 0，公式失效。这时退化为**积分 `Wx`（滚转角速度）**，
   并规定 `|Wx| < 2°/s` 时用约 4 秒缓慢衰减回平飞。纯积分没有绝对参考，所以必须靠这个衰减防止漂移
   （早期版本无衰减实测漂到 -170°）。

## 5. 置信度与淡出

- GAME 模式：置信度恒为 1。
- EST 模式：置信度初始 1；当 `|Ny - 1| > 4`（剧烈机动）时噪声因子降到 0.75，置信度缓慢下降、之后缓慢恢复。
- 渲染时姿态符号的透明度 = 置信度；地面/未起飞/数据断流 → `Unavailable`，姿态类符号整体淡出，
  速度/高度/数据块照常显示（避免地面 AoA 噪声导致梯子乱跳）。

## 6. 界面上的标记

- 右下角 **`AHRS EST`（琥珀色）**：估算姿态；**`AHRS GAME`（淡绿）**：原生地平仪。可在显示页关掉来源标签。
- **坡度耦合**（`rollCouplingMode`）不是修 EST 误差的，它处理的是**相机参考系**：
  - 第三人称相机不跟飞机滚转 → 真实地平线在屏幕上是水平的，梯子不该跟着滚（耦合 0）
  - 座舱视角相机跟飞机一起滚 → 梯子要反着转回去（耦合 1）
  - `auto` 默认按拟真玩法取 1；觉得第三人称下梯子转得不对，可在设置里改 `off`。

## 7. 已知边界（诚实说明）

| 场景 | 表现 |
|---|---|
| 大 G 急拉/筋斗 | 坡度跟随有约 0.1–0.3 s 滞后；俯仰因低通也略滞后 |
| 乱流/热气流 | Vy 含气流垂直分量 → 俯仰有偏差 |
| 侧滑飞行 | AoA 仍是机身纵向角，俯仰基本对，但机头与航迹有夹角（看 FPM） |
| 低速/悬停 | TAS < 5 km/h 时 γ 直接取 0；低速段噪声大 |
| 无罗盘机型 | 坡度靠滚转率积分，长时间会缓慢漂（已加回平衰减） |
| 与座舱仪表对比 | EST 不是陀螺仪，没有积分漂移，但会有滞后/风偏，**不会逐帧一致** |

合成轨迹自测（`WtHud.exe fusiontest`）要求俯仰/坡度误差都 **< 6°** 才算通过：
平飞、3°/s 转弯（坡度≈53°）、筋斗大 G（坡度≈0、俯仰≈34°）三个场景。

## 8. 用户能做的校准/调整

| 现象 | 做法 |
|---|---|
| 平飞时梯子不指 0 | 平飞按 **F7**（记 `pitchZeroDeg`） |
| 坡度方向反了 | 按 **F8**（`bankSign`） |
| 机型原生俯仰符号相反（F-4J、MiG-19 等） | 不用管：HUD 自动投票学习并存进 `airframes.json`；也可手动设 `pitchSign` |
| 整体上下偏/角度刻度不对 | `Ctrl+Alt+↑/↓` 调布局偏移；`Ctrl+Alt+PgUp/PgDn` 调视场角 |
| 第三人称下梯子滚转怪 | `rollCouplingMode` 改 `off` |
| 想确认当前是哪种模式 | 看右下 `AHRS EST/GAME`；日志每 2.5 s 打 `att=Estimated pitch=... bank=... conf=...` |

## 9. 常见问题

**Q：为什么有的飞机是 GAME，有的是 EST？能切吗？**
A：取决于游戏 API 给不给地平仪数据，不是 HUD 的选择。没有开关是故意的——有原生数据还用估算只会更差。

**Q：EST 会不会越飞越偏？**
A：不会累积漂移（俯仰/坡度都不用积分），但会有滞后和风偏；无罗盘机型例外，靠滚转率积分，已加回平衰减。

**Q：为什么大 G 时梯子/坡度看起来"慢一下"？**
A：俯仰有低通、坡度有限速，且高 G 时置信度下降。这是为了避免噪声让梯子抖，属于设计取舍。

**Q：EST 的俯仰和座舱地平仪差 1–2° 正常吗？**
A：正常，尤其在乱流或大机动时。平飞无风环境下应基本一致；系统性偏差用 F7 校准。
